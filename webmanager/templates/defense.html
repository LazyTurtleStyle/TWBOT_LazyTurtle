Arm cancel snipe

The troops below leave for the target above and are cancelled mid-flight, so they walk back in and are home at first hit + aim — never before it, which is the whole point: home early means home for the hit you were dodging.

First hit ms
The .mmm of the attack you are sniping. Filled in for you.
Land +ms after it
How far into the gap to come home — after the hit, always. This counts the opposite way to the Snipe tab next door, whose offset is negative because support has to be standing there before the command it is meeting; here the stack has to be out when the hit lands. Lone incoming: 300–500. Noble train: just past the first hit — 100 ms gaps are makeable.
No later than +ms alpha
Only for a gap that is fatal on both sides. Set it to the next hit's offset minus a margin: the bot aims the middle of that window and, when a send would miss it, cancels and re-fires on a later 2-second slot until one lands inside. Needs a few minutes of lead, ~10–15 s per retry, 8 tries. Leave empty otherwise.
Engage (min before)
When the bot starts. It must be able to send and still be under way at the halfway moment, which is where the cancel goes.

How close it lands: +30–90 ms once the throwaway one-unit probes have measured today's send timing, +150–400 ms without them, and +2 s on a badly jittered send. Late, never early — the server credits a cancelled command's flight in whole seconds, so the return carries the send's millisecond and a send that slips only rolls it one 2-second slot later. The log's "send bias" line says which of the three you are getting.

Dry-run the cancel snipe with no incoming attack: pick a village, set the moment the troops must be back home, and the bot runs the exact same flow it would against a real train, send toward a far barb, measure the send to the millisecond, cancel at the halfway moment. The result row shows the achieved return and its ±ms against your target, so you can verify the timing on this world/connection before trusting it with a real train. Use the same troops you would dodge with.

Set up a test snipe
The two fields together are the full return moment HH:MM:SS:mmm. The ms field is part of the time, not a margin. A time in the past means tomorrow. Aim at a non-zero millisecond (e.g. .250): an uncancelled return always lands on .000, so hitting near your ms proves the cancel mechanic worked. Like a real snipe the return is never early, expect it 30–90 ms late when the send-bias probes succeed (watch the log), 150–400 ms without them, +2 s on a badly-jittered send; the ±ms badge on the result is your verdict, and it reads the achieved return from the in-game command list, not the cancel screen. With Window +ms set the return must land within that many ms past the target: the bot aims mid-window and re-fires missed sends (cancel, wait home, next 2-second slot) until one is inside, the result line then reports window HIT or MISSED. Try +100 to see the retry loop work.
